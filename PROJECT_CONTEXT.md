## 0. TL;DR

* **Кейс:** хакатон МТТЕХ «ИИ-прогноз загрузки трамвайных маршрутов». По 10 месяцам валидаций (янв–окт 2025, 10 ГБ сырых CSV)
  спрогнозировать **число посадок по часам** для 10 маршрутов на **ноябрь–декабрь 2025** → файл `submission.csv`
  (14 640 строк), метрика **WAPE-score = 1 − Σ|y−ŷ|/Σy**, baseline организаторов ≈ **0.48**. Плюс — веб-сервис с картой.
* **Модель:** не нейросеть и не бустинг, а **робастная профильная мультипликативная модель**
  (профиль маршрут × тип дня × час) × тренд × календарь × погода. Бэктест (5 окон) — **WAPE-score 0.887**,
  «потолок» постановки ≈ 0.93. LightGBM-корректор пробовали — ухудшал, отвергнут.
* **Сервис:** FastAPI (REST + WebSocket) + React 19/TypeScript + MapLibre, Docker Compose. Главный экран —
  «пульт оператора»: карта Москвы на весь экран, лента времени как в видеоредакторе, подсветка перегруженных веток,
  карточка маршрута/остановки с рекомендацией «+N вагонов». Разделы (Сводка, Прогноз и выгрузка, Под капотом,
  Модель, Сервис и API) — отдельные полноэкранные страницы.
* **Запуск:** `DATASET_DIR=../dataset docker compose up --build` → UI http://localhost:8080, Swagger http://localhost:8000/docs.

## 1. Описание кейса (постановка)

Источник — `dataset/README.md` из архива организаторов (другой официальной постановки в репозитории нет).

### 1.1 Главное
* Даны **только январь–октябрь 2025**: `train.csv` (янв–авг) и `test.csv` (сен–окт) — сырые валидации (~62,4 млн строк, 10,4 ГБ).
* **Ноябрь–декабрь 2025 не выдаются** — это период прогноза. Проверка по скрытому эталону `ground_truth`.
* Это классический прогноз временного ряда «на 2 месяца вперёд по часам»; ответ нельзя посчитать, только предсказать.

### 1.2 Целевая величина
```
boardings(route, date, hour) = число успешных валидаций (validation_result == 1)
                               на маршруте route (из ngpt_route, «25 трамвай» → 25)
                               за календарный час hour даты date (по tran_date_time)
```

### 1.3 Данные
| Файл | Что это |
|---|---|
| `train.csv`, `test.csv` | сырые валидации, разделитель `;`: `tran_no, device_no, tran_date_time, begin_date_time, input_date_time, crd_hashcode, validation_result, tran_type_id, place_id, good_type, pass_route, ngpt_route, bus_exit_no, garage_number` |
| `labels/labels_day_{train,test}.csv` | готовые почасовые агрегаты `route;date;hour;boardings` |
| `test_submission.csv` | пример формата (baseline ≈ 0.48) |
| `spravochniki/` | справочники остановок с координатами (пересекаются с данными только по маршрутам {1,5,7,11,12}) |

Особенности, оговорённые организаторами:
1. `input_date_time` битый — использовать `tran_date_time`.
2. Файлы содержат суточный «хвост» в следующий месяц — агрегировать строго по дате из `tran_date_time`.
3. `pass_route` зашумлён — маршрут брать из `ngpt_route`.
4. `place_id` — площадка/депо, **не остановка**; остановочная детализация — «необязательный бонус».
5. Маршрут `5` встречается редко.

### 1.4 Формат решения
`route;date;hour;prediction`, полная сетка **10 маршрутов × 61 день × 24 часа = 14 640 строк**, prediction ≥ 0.

### 1.5 Метрика
`WAPE = Σ|y − ŷ| / Σy`, `WAPE-score = max(0, 1 − WAPE)`, больше — лучше. Устойчива к нулям (ночь),
доминируют дневные/пиковые часы крупных маршрутов.

### 1.6 Требования к веб-сервису (как мы их поняли из описания кейса)
Сервис для диспетчеров (ЕДЦ): прогноз на горизонты **день / месяц / год**; агрегация по **маршруту, остановке, интервалу**;
**карта** с динамикой загрузки; **корректирующие коэффициенты** (погода, события, сезон…); **выгрузка** CSV/XLSX;
прозрачность («что под капотом»); производительность/масштабируемость; бизнес-ценность (распределение вагонов,
снижение переполнения). Точные критерии оценки жюри в репозитории **не зафиксированы** — это допущение.

## 3. Данные и конвейер (backend)

Конвейер — `backend/app/pipeline.py`, 9 стадий, каждая шлёт события в шину → WebSocket `/ws/pipeline` (UI «Под капотом»):

1. **ingest** — DuckDB читает сырые CSV → `data/raw_hourly.parquet` (посадки, отказы, уникальные карты, число вагонов по `garage_number`, тарифы). Кэш зашит в образ, сырые CSV не обязательны.
2. **normalize** — полная сетка 10 × 304 дня × 24 ч (72 960 ячеек, 15 409 дозаполненных нулей), сверка с `labels`. Маршрут 5: 0 посадок за 10 месяцев → прогноз 0.
3. **external** — календарь РФ 2025–26 (праздники, переносы, 01.11.2025 — рабочая суббота), школьные каникулы Москвы, погода Open-Meteo (ERA5, почасовая).
4. **geo** — геометрия маршрутов и остановки из OpenStreetMap (Overpass), веса остановок, «пучки» общих участков (1 050 отрезков, 312 общих), схема (выпрямленная сеть).
5. **features** — профили, выпуск вагонов по часам (медиана 6 недель), **норматив посадок на вагон = p95 истории маршрута**.
6. **backtest** — 5 окон × 4 варианта модели (абляция).
7. **train** — финальная модель на 28 днях до 31.10.2025.
8. **forecast** — 01.11.2025 … 31.10.2026 по часам с разложением на компоненты → тензор `[10 × 365 × 24]` на компоненту.
9. **export** — `submission.csv`, `forecast_components.parquet`.

Кэши внешних данных — в `data/` (`fetch*()` в `backend/app/ml/*.py`).

## 4. Модель (`backend/app/ml/model.py`)

```
ŷ(route, date, hour) = P[route, класс дня, hour]   — усечённое среднее (trim 20%) за 28 дней до точки прогноза
                     × trend[route]                 — последние рабочие дни вне каникул / окно
                     × calendar[date]               — праздник → воскресный профиль × множитель;
                                                      01.11 рабочая суббота; 29–30.12 предновогодние; 31.12 вечер ×0.55
                     × weather[date]                — сильные осадки (> 6 мм/сутки) → ×0.974 (коэф. доверия 0.5)
                     × season[month] × event        — только для горизонта «год» и сценариев из UI
```
Классы дня: пн / вт–чт / пт / сб / вс+праздники.

**Почему так, а не ML «посерьёзнее».** 10 месяцев данных = одна реализация сезона; целевой период (ноябрь–декабрь)
в истории отсутствует. Глобальные модели учат сезонный дрейф как «эффект признаков». Метрика WAPE вознаграждает
точный уровень в дневные часы — робастный профиль + калибровка тренда даёт это лучше всего.

**Что пробовали и отвергли (важно для обсуждения):**
* LightGBM-корректор остатков (цель y/ŷ, вес ŷ, L1; признаки: погода по часам, календарь, час, маршрут): 0.8875 → 0.864–0.878. Причина — летний спад в остатках обучающих окон.
* 7 классов дня вместо 5: 0.8796. Смесь окон 21+42 дня: 0.8810. Погодный множитель по всем корзинам осадков: 0.8834.
* Без исключения недели осенних каникул (27–31.10) тренд занижал ноябрь на 3–5% на маршрутах 1, 7, 25, 28.

Варианты сабмита с поправкой уровня: `submissions/submission_scale_{0.97,1.00,1.03}.csv`, `python -m app.cli --scale 1.02`.

## 5. Бэкенд: сервис

| Модуль | Файл |
|---|---|
| API (REST + 3 WS, ошибки 400/409/503 на русском, метрики) | `backend/app/main.py` |
| Хранилище: тензоры прогноза, срезы, коэффициенты, экспорт, `/api/day` | `backend/app/store.py` |
| Конвейер | `backend/app/pipeline.py`, шина событий `events.py` |
| ML-модули | `backend/app/ml/{aggregate_raw,calendar,weather,geo,model}.py` |
| CLI для сабмита | `backend/app/cli.py` |

Ключевые эндпоинты: `/api/forecast` (horizon day|month|year, route, stop_id, hour_from/to, agg, by_route, коэффициенты),
`/api/forecast/export` (CSV/XLSX), `/api/day` (сутки целиком: посадки, вагоны, загрузка, дефицит по маршрутам × 24 ч — основа пульта),
`/api/decompose`, `/api/recommendations`, `/api/geo` (линии, остановки, «пучки» `segments`, схема `schema`, список всех 36 трамваев Москвы `all_routes`),
`/api/meta`, `/api/model`, `/api/history`, `/api/submission`, `/api/system`, `POST /api/pipeline/run`;
WS: `/ws/pipeline`, `/ws/live`, `/ws/system`.

**Почему быстро:** запрос = срез numpy по тензору и перемножение с коэффициентами (~0.4 мс), LRU-кэш, orjson, gzip.
Сервис без состояния → горизонтальное масштабирование репликами (для WS конвейера нужен sticky-session/Redis).

**Индекс загрузки и рекомендации:**
`ratio = (посадки в час / вагонов на линии) / норматив`, норматив = p95 посадок на вагон по маршруту.
Уровни: < 70% свободно, 70–100% норма, 100–120% «внимание», > 120% «перегрузка».
Рекомендация: сколько вагонов добавить, чтобы вернуться к нормативу, и в каком окне часов.

## 6. Фронтенд и UX (`frontend/src`)

Стек: React 19 + TypeScript + Vite, MapLibre GL (подложка OpenFreeMap positron), Recharts, иконки lucide-react. Сборка → nginx.

### 6.1 Главный экран — «пульт оператора» (`ops/`)
* **Карта на весь экран** (`OpsMap.tsx`), ограничена Москвой.
  * Ветки в **официальных цветах** маршрутов (Транспорт Москвы). На общих участках — параллельные «пучки» (line-offset), как на официальной схеме.
  * **Номера маршрутов** — прямые цветные бейджи на конечных (раньше были вдоль линии — искажались на изгибах).
  * **Проблемные ветки** — чёткая цветная обводка (красная > 120%, оранжевая 100–120%), пульсирует; бейдж на ветке «№26 · +29%».
  * **«Дыхание» города** — heatmap спроса у остановок (бирюзово-голубой), нормирован на пик суток: ночью гаснет, в пик разгорается.
  * **Горячие точки** — у 4 самых загруженных остановок перегруженной ветки размытое оранжево-красное свечение + расходящееся кольцо.
  * **Таймлапс:** значения часа держатся весь час (совпадают с бейджами), за последние 20 минут плавно перетекают в следующий час (smoothstep). Анимация — в собственном rAF-цикле карты (~12 обновлений/с), без перерисовки React.
  * **Режимы «Карта / Схема»** — кнопка справа (над «+ −»). «Схема»: без дорог, только фон и бледная вода; пути автоматически выпрямлены (слияние участков в цепочки → привязка к сетке 80 м → Дуглас–Пекер 230 м → октилинейность 45°/90°, один путь на маршрут), остановки спроецированы на линии, при приближении видны все остановки и названия.
  * Справа: «?» (о проекте и легенда), «Карта/Схема», «+», «−».
* **Лента времени** (`Timeline.tsx`) — как дорожка видеоредактора: неподвижный указатель по центру, лента прокручивается.
  Перетаскивание с инерцией, клик — плавный переход, колесо/трекпад, Ctrl/⌘+колесо — масштаб 2–24 ч; соседние сутки видны
  по краям, переход через полночь меняет дату. Под лентой — монохромная «волна» пассажиропотока сети, ⚠ в часы перегрузки.
  Клавиши: ← → шаг 15 мин, удержание — плавная перемотка (30→180 мин/с) через сутки; пробел — пуск/пауза; Esc — назад.
  Верхняя строка: [☰] [▶ │ ×1] [‹ 📅 дата ›] [● Live] … «Среда 08:00 +3° ☁». Скорость по кругу 0,25–0,5–1–1,5–2–4–8.
  Свой календарь (дни → месяцы → годы). **Live** — лента идёт с реальными часами, мигающая красная точка, красный указатель; любое ручное действие выходит из Live.
* **Бейджи проблем** под лентой: `26 +29%` (показывается только превышение норматива). На телефоне — сводка «⚠ 9 веток выше нормы ⌄» с раскрытием.
* **Панель номеров** внизу (`RouteBar.tsx`): 10 маршрутов с данными в цветах + разделитель + 26 остальных трамваев Москвы неактивными (всего 36, из OSM, без служебных т1/т2); прокрутка при нехватке места.
* **Карточка ветки** (`RoutePanel.tsx`, плавающее стекло слева; на телефоне — шторка снизу):
  * режим «ветка»: загрузка в выбранный час, одна строка рекомендации (+N вагонов на окно), 3 факта, мини-график суток, окна перегрузки, топ-3 остановки, выгрузка XLSX;
  * режим «остановка» (клик по точке): посадки на остановке в этот час, доля потока, график по часам, пересадки рядом (≤ 250 м, клик переводит на другой маршрут), ‹ › по соседним остановкам, выгрузка.
* **Меню** — кнопка ☰ внутри ленты; выпадающий список (на телефоне — на весь экран): разделы, «Коэффициенты», «О проекте и легенда».
* **Коэффициенты** (погода, событие/перекрытие, сезон, тренд, праздники) — скрыты в меню; если изменены — плашка «коэффициенты изменены ×» под лентой.
* **Приветствие** (`Intro.tsx`) при первом входе: WAPE-score 0,887 с полоской и отметкой baseline 0,48, 3 шага «как читать карту», кнопки «Открыть карту» и «submission.csv».

### 6.2 Разделы (`pages/`) — полноэкранные страницы с адресом `#overview`, `#forecast`, `#pipeline`, `#model`, `#service`
Верхняя стеклянная панель «← Карта» + переключатель разделов; «Назад» браузера возвращает к карте.
* **Сводка** — KPI прогноза, график факт (сен–окт) + прогноз (ноя–дек), по маршрутам, профиль суток, «где не хватает вагонов».
* **Прогноз и выгрузка** — горизонт/дата/часы/агрегация/остановка/маршруты, CSV/XLSX, `submission.csv`.
* **Под капотом** — 9 стадий с прогрессом, живой журнал, пересчёт из сырых 10 ГБ, архитектура.
* **Модель** — формула, бэктест, абляция, WAPE по маршрутам, множители, область применимости.
* **Сервис и API** — RPS/p50/p95/CPU/RAM в реальном времени, нагрузочный тест из браузера, эндпоинты.

### 6.3 Дизайн-система и адаптив
Тёмное «стекло» (`rgba(11,17,32,.82)` + blur), нейтральные плашки `--surface`, акцент `#22d3ee` только по смыслу;
цвет — загрузка и номера маршрутов. Адаптив: ≥ 1181 / 901–1180 / 721–900 / ≤ 720 px; container queries сокращают подписи
ленты (год → день недели → месяц «ноя»). Телефон: лента сверху, карточка — шторка снизу, меню и коэффициенты на весь экран.
Проверено на 375, 768, 1024, 1280, 1440, 1920 px.

## 7. Спорные моменты, риски и честные ограничения

**Модель и сабмит**
1. **Погода за целевой период.** В сабмите используется *фактический архив* Open-Meteo за ноябрь–декабрь 2025.
   Формально это информация «из будущего» относительно момента прогноза (31.10.2025). Эффект мал (множитель 0.974 только
   для дней с осадками > 6 мм), но на защите об этом лучше сказать прямо; честная альтернатива — климатическая норма или прогноз погоды.
2. **Экспертные множители** предновогодних дней (29–31.12) и 31.12 вечер ×0.55 — в истории нет прошлого декабря, заданы вручную.
3. **Сезонность ноября–декабря** не наблюдалась. Приняли «ноябрь ≈ октябрь» по аналогии с февралём–мартом. Если есть сезонный спад/рост — уровень промахнётся (отсюда варианты `scale 0.97/1.03`).
4. **Маршрут 5 = 0.** Организаторы пишут «встречается редко», у нас 0 посадок за 10 месяцев. Если в эталоне он ненулевой — небольшой штраф.
5. **Бэктест ≠ целевой период**: окна весна/осень; майские праздники просаживают до 0.85. Для декабря с праздниками ожидаемо ниже среднего 0.887.
6. «Потолок 0.93» — оценка через «оракула», а не строгая граница.

**Загрузка и рекомендации (бизнес-слой)**
7. **Посадки ≠ пассажиры в салоне**: нет выходов и безбилетников. «Загрузка» — это посадки на вагон к нормативу, а не заполненность салона.
8. **Норматив = p95 истории маршрута** — прокси вместимости; перегрузка определяется *относительно обычного для маршрута*, а не паспортной вместимости вагона.
9. **Вагоны на линии в прогнозе** — медиана выпуска за 6 недель, а не плановое расписание. Рекомендация «+N вагонов» — упрощённая арифметика.

**Геоданные и остановки**
10. **Остановочная детализация оценочная**: в данных нет остановки посадки. Поток маршрута делится по весам (пересадочные узлы ×2.5, конечные ×1.8, прочие ×1). Поэтому график по остановке — масштабированная копия маршрута.
11. Геометрия и остановки — из OpenStreetMap (справочники покрывают только 1, 5, 7, 11, 12). Возможны неточности OSM (кавычки в названиях, дубли).
12. **Схема** строится автоматически — это не официальная схема; расстояния/пересечения местами неидеальны, вода не согласована с выпрямленными линиями.
13. Список 36 маршрутов Москвы — выгрузка OSM на 26.09.2026 (без т1/т2); 26 из них в UI неактивны (нет данных).

**Сервис и UI**
14. Заявлено «работает без сети», но **подложка карты (OpenFreeMap) грузится из интернета**; без сети карта будет без тайлов (линии и данные останутся).
15. Горизонт до 31.10.2026 — **сценарный** (сезонный индекс по одной реализации сезона), не провалидирован. Live-режим (сегодня 2026) показывает именно этот сценарный прогноз.
16. Нагрузочные цифры сняты на MacBook в Docker Desktop, 1 процесс uvicorn; в проде будет иначе.
17. Иногда в консоли видны переподключения WebSocket `/ws/pipeline` (после рестарта контейнера) — есть автопереподключение.
18. Автотестов фронтенда нет; проверка — ручная в браузере на разных ширинах. Бэкенд проверяется бэктестом и сверкой с labels.

## 10. Что можно обсудить / улучшить дальше

* Честный вариант сабмита без фактической погоды (климатическая норма) — сравнить на бэктесте, выбрать для защиты.

* Вероятностные интервалы (квантили) и согласованность остановка → маршрут → сеть.
* Офлайн-тайлы подложки (PMTiles) для работы полностью без сети.

## 11. Краткая история решений по интерфейсу (чтобы не откатить случайно)

* Лента времени — не слайдер, а прокручиваемая дорожка; без цветной «тепловой полосы» (только ⚠ и монохромная волна).
* Эмодзи запрещены — только иконки lucide.
* Метка «выходной» убрана; счётчик «N перегр.» заменён бейджами под лентой; проценты — только превышение «+29%».
* Кнопка «Карта/Схема» переключает сразу (без меню), стоит над «+ −».
* Меню — внутри ленты (не отдельный плавающий бургер); на телефоне всегда в ленте, лента всегда сверху.
* Карточка ветки — плавающее стекло, крестик вверху; разделы — полноэкранные страницы, не модалки.
* Номера маршрутов — бейджи на конечных, не вдоль линии.
* Кнопка даты фиксированной ширины (не «скачет» при листании).
